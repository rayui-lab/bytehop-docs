这页面向负责部署 ByteHop 的管理员。普通使用者不需要执行这里的命令；已有 Server 地址和账号时，应从[第一次使用](/docs/quickstart)开始。

## 你要部署的是 Server

团队只需要运行一个 ByteHop Server。它提供 Web、控制 API 和 HTTP 数据面，并保存用户、Resource、Lease 与 Event。每位成员的 CLI 和 Skill 都连接这个 Server。

```text
成员电脑                                      团队服务器
Web / CLI / Agent + Skill  ── HTTPS ──>  ByteHop Server  ──>  数据库 / API
```

CLI 与 Server 来自同一个 `bytehop` 二进制，但职责不同：服务器运行 `bytehop serve`；成员电脑运行 `login`、`resources`、`request` 和 `connect`。生产环境推荐用 Docker Compose 运行 Server。

## 管理员完成五件事

| 步骤 | 管理员输入 | 完成结果 |
| --- | --- | --- |
| 1. 部署 Server | Linux 主机、域名、Docker | 团队可访问的 HTTPS 地址 |
| 2. 接入 Resource | 上游地址和固定最小权限身份 | `analytics` 等 Resource |
| 3. 创建用户 | 独立用户名、初始密码、用户组 | 成员可以登录 ByteHop |
| 4. 分配权限 | user / group 到 Resource 的 Access policy | 成员只看到获准 Resource |
| 5. 交付给成员 | Server 地址、账号、用途说明 | 成员按第一次使用完成验证 |

ByteHop v0.1 没有公开注册。账号由管理员写入 `bytehop.yaml`，密码通过环境变量注入。成员拿到的是 ByteHop 账号，不是数据库账号。

## 部署前准备

- 一台能访问上游数据库或 API 的 Linux 主机；
- 指向该主机的 HTTPS 域名；
- Docker Engine 与 Docker Compose；
- 至少一个上游固定最小权限身份；
- 用于首个 ByteHop 管理员账号的随机密码。

## 推荐部署方式

使用 Release 中的生产 Compose 示例，它只长期运行 ByteHop 与 Caddy：

[使用 Docker 部署](/docs/administration/docker)

需要自定义进程管理或构建 ByteHop 本身时，再使用[从源码构建](/docs/development/source-build)。普通成员安装 CLI 和 Skill 的方法在[安装客户端](/docs/using/client-installation)。

## Server 启动后

1. 使用 `.env` 中的 `BYTEHOP_ADMIN_PASSWORD` 和 `admin@example.com` 登录 Web；
2. 确认 **Resources** 中的首个 Resource 可以发现；
3. 在 `config/bytehop.yaml` 中为每位成员增加独立用户和最小用户组；
4. 配置 Access policy 后校验并应用；
5. 用一个普通成员账号登录，验证应显示和不应显示的 Resource；
6. 通过安全渠道交付 Server 地址、用户名和初始密码。

账号写法见[用户管理](/docs/administration/member-lifecycle)，Resource 授权规则见[权限模型](/docs/administration/access-leases)，数据库和 API 接入见[接入 Resource](/docs/administration/resource-onboarding)。

## 交给成员的信息

不要只发一句“ByteHop 已经好了”。至少提供：

```text
ByteHop 地址：https://bytehop.example.com
用户名：alice@example.com
初始密码：通过团队 Secret 渠道发送
已授权 Resource：analytics
用途：只读查询生产指标
开始文档：https://rayui-lab.github.io/bytehop-docs/docs/quickstart/
```

不要发送 ClickHouse 密码、MongoDB URI、API Key 或 ByteHop Server 的 `.env`。成员只需要 ByteHop 地址和自己的 ByteHop 账号。
