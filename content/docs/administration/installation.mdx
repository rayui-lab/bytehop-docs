---
title: 安装 ByteHop
description: 使用官方二进制或容器镜像安装同一版本的服务端与 CLI。
---

ByteHop 的服务端和 CLI 是同一个二进制文件。团队管理员通常用容器运行服务端，成员从同一个 GitHub Release 下载本机 CLI；两者固定为相同版本。

## 选择安装方式

| 使用场景 | 推荐方式 |
| --- | --- |
| 在 Linux 主机部署团队实例 | [Docker Compose](./docker) |
| 在 macOS、Linux 或 Windows 安装 CLI | GitHub Release 二进制 |
| 修改 ByteHop 本身 | [从源码构建](../development/source-build) |

## 安装预编译二进制

每个 Release 提供以下平台：

| 操作系统 | 架构 | 文件 |
| --- | --- | --- |
| Linux | amd64、arm64 | `.tar.gz` |
| macOS | amd64、arm64 | `.tar.gz` |
| Windows | amd64、arm64 | `.zip` |

以 Linux amd64 和 `v0.1.0` 为例：

```bash
VERSION=0.1.0
curl -fLO "https://github.com/rayui-lab/bytehop/releases/download/v${VERSION}/bytehop_${VERSION}_linux_amd64.tar.gz"
curl -fLO "https://github.com/rayui-lab/bytehop/releases/download/v${VERSION}/SHA256SUMS"
grep "bytehop_${VERSION}_linux_amd64.tar.gz" SHA256SUMS | sha256sum -c -
tar -xzf "bytehop_${VERSION}_linux_amd64.tar.gz"
sudo install -m 0755 "bytehop_${VERSION}_linux_amd64/bytehop" /usr/local/bin/bytehop
bytehop version
```

macOS 使用对应的 `darwin_amd64` 或 `darwin_arm64` 包，并把校验命令换成 `shasum -a 256 -c`。Windows 解压 `.zip` 后，将 `bytehop.exe` 放进受控的软件目录并加入 `PATH`。

<Callout title="先核对再安装">
  校验和文件与二进制必须来自同一个 Release。不要从聊天附件、临时网盘或不明镜像分发 ByteHop。
</Callout>

## 服务端需要准备什么

- 一台能访问上游数据库或 API 的 Linux 主机；
- HTTPS 域名，或团队已有的可信入口网关；
- ByteHop YAML、通过环境变量注入的 Secret 和持久数据目录；
- 数据库或 API 管理员预先创建的固定最小权限身份。

服务端启动后，按以下顺序完成接入：

1. [使用 Docker 部署](./docker)；
2. [接入 Resource](./resource-onboarding)；
3. [配置权限](./access-leases)；
4. [管理成员](./member-lifecycle)；
5. 让成员按[第一次使用](../quickstart)完成登录与查询。
