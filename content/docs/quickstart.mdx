title: 第一次使用

---

这页面向 ByteHop 使用者。前提是管理员已经部署好 Server，并为你创建了独立账号。你不需要运行 Docker、编辑服务端 YAML，也不需要知道数据库密码或内部 API Key。

## 先向管理员拿到三项信息

| 信息 | 示例 | 用途 |
| --- | --- | --- |
| ByteHop Server 地址 | `https://bytehop.example.com` | Web 和 CLI 都连接这个地址 |
| 用户名和初始密码 | `alice@example.com` | 登录 ByteHop，不是数据库账号 |
| 已授权 Resource | `analytics` | 判断登录后的资源列表是否正确 |

v0.1 没有公开注册。账号由管理员创建，并通过团队已有的安全渠道交付初始密码。如果还没有 Server 地址或账号，请让管理员从[部署 ByteHop](/docs/administration/installation)开始。

## 1. 先用 Web 确认账号

在浏览器打开管理员提供的 Server 地址并登录。进入 **Resources** 后，只应看到当前账号获准使用的 Resource。

只需要查看 Resource、自己的访问和 Event 时，到这里已经可以使用，不必安装 CLI。

## 2. 需要终端或 AI 时安装 Client

如果需要运行查询、调用内部 API、使用脚本或让 AI Agent 工作，在用户或 Agent 所在的电脑安装 CLI：

```bash
curl -fsSL https://raw.githubusercontent.com/rayui-lab/bytehop-dist/main/install.sh | sh
bytehop version
```

Windows、固定版本和 Skill 安装见[安装客户端](/docs/using/client-installation)。CLI 是连接已有 Server 的 Client；运行这条命令不会在本机部署 ByteHop Server。

## 3. CLI 登录一次

把地址和用户名换成管理员提供的值。密码只在当前终端读取，不写进 shell history：

```bash
read -s BYTEHOP_PASSWORD
printf '%s\n' "$BYTEHOP_PASSWORD" | \
  bytehop login https://bytehop.example.com \
  --user alice@example.com --password-stdin
unset BYTEHOP_PASSWORD
```

登录成功后，CLI 在本机保存一个权限为 `0600` 的 ByteHop Session。它只能连接 ByteHop，不是数据库或内部 API 的上游凭证。

Web 与 CLI 使用同一个账号，但各自保存独立 Session。在 Web 登录不会让另一台电脑上的 CLI 自动登录。

## 4. 查看自己能访问什么

```bash
bytehop resources
bytehop resources analytics --json
```

第一条命令只列出当前账号获准的 Resource；第二条查看其中一个 Resource 的用途和调用说明。列表与管理员承诺不一致时，让管理员检查你的用户组与 Access policy，不要猜名称或尝试数据库连接串。

## 5. 选择由谁调用

### 人直接使用 CLI

以下是 ClickHouse HTTP Resource 示例：

```bash
printf '%s' 'SELECT count() FROM events FORMAT JSON' |
  bytehop request analytics POST / \
  --body @- --content-type text/plain --json
```

`request` 自动创建一次短期 Lease，请求完成后撤销。结果会带 `request_id`，ClickHouse 还会带 `query_id`。

### 让 AI Agent 使用

先安装 [ByteHop Skill](/docs/using/agent-workflow)，重新开始 Agent 会话，再直接描述结果：

```text
请使用 ByteHop 查询最近一小时各服务的事件数量，最多返回 20 行，并保留 request_id。
```

Skill 会让 Agent 先运行 `bytehop resources --json`，再读取单个 Resource 的调用说明并选择 CLI 命令。CLI 必须已经安装和登录；Skill 不包含二进制、账号或权限。

Hermes 用户参见[在 Hermes 与飞书中使用](/docs/using/hermes)。

## 6. 查看和结束自己的访问

在 Web 的 **My access** 查看正在运行的请求，在 **My activity** 查看历史 Event。CLI 也可以查看状态或退出：

```bash
bytehop status --json
bytehop logout --json
```

`logout` 会撤销当前 CLI Session 及其派生 Lease。共用电脑或任务结束后应主动退出。

## 仍然不能使用时

- 没有 Server 地址或账号：联系 ByteHop 管理员；
- 登录失败：确认 URL、用户名和初始密码，管理员可能已修改或停用账号；
- Resource 列表为空：登录成功但尚未获得 Access policy；
- Agent 说找不到 `bytehop`：在 Agent 所在的同一台机器安装 CLI；
- Agent 不知道如何调用：安装 Skill 并开始新会话。

更多错误处理见[故障排查](/docs/administration/troubleshooting)。
