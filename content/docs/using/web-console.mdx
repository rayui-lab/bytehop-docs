---
title: Web 管理界面
description: 普通成员与管理员分别能在 ByteHop Web 界面完成什么。
---

Web 界面是资源入口和轻量观察面，不是在线 SQL 编辑器，也不维护另一套配置数据库。

## 普通成员

- **Resources**：查看自己能用的 Resource，复制 Agent、CLI 和现有 HTTP client 用法；
- **My access**：查看和撤销自己的 Lease，查看当前运行请求；
- **My activity**：按时间查看自己的访问 Event；
- **Profile**：确认当前身份、组和实例环境。

资源详情不会展示 upstream 或 credential，也不会在浏览器 JavaScript 中生成 Lease token。真正的调用交给 CLI 或 Agent。

## 管理员

- **Access**：查看身份、组和策略形成的访问结果；
- **Sessions**：查看当前 Lease 与运行中 Operation，停止单个 ClickHouse 查询；
- **Events**：按身份、资源和时间排查历史调用；
- **System**：检查待加载配置、预览 diff 并执行安全热重载。

## 运行中查询与历史 Event

运行中查询来自当前进程的活动请求，并用 ByteHop 生成的 ClickHouse `query_id` 与 `system.processes` 对照。查询结束后它会从 Sessions 消失；历史 SQL 留在 Event 中。

普通成员只能看和停止自己的请求，管理员可以处理全部 ByteHop 请求。ByteHop 不枚举绕过网关直接发起的数据库查询。

## Web 会话安全

Web 登录使用 `HttpOnly`、`SameSite=Strict` Cookie，token 不进入 JSON，也不暴露给前端脚本。会改变状态的 Cookie 请求要求 `Origin` 与 `server.public_url` 同源。

若注销时网络或服务端失败，界面保留登录状态并显示错误；这样刷新后不会出现“已退出但会话仍有效”的假象。
